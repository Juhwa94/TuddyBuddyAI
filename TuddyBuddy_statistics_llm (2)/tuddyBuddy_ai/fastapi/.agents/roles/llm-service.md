# LLM service agent

Own provider integration, prompt construction, structured LLM output, and analysis behavior in `service/llm_service.py` and `common.py`. Keep deterministic score/statistical calculations and output validation in Python when feasible; prompts alone do not enforce these requirements. Handle provider and structured-output failures explicitly, and avoid unnecessary user-data logging. Retrieve project guidance through `rag/` and coordinate corpus/retrieval changes with the RAG owner. Preserve configured provider/model behavior and never inspect or expose `.env` values. Coordinate input/output model changes with the schema and response-filter owners; coordinate changes to shared configuration in `common.py`. Report model assumptions, failure modes, and files touched. Do not edit route/schema files unless explicitly coordinated.
